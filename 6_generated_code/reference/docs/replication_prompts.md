# Replication Package — Prompt Protocol
## Regenerating the Flight Simulator from a SysML v2 Model with an LLM Developer

**Scope.** This document isolates the complete, ordered sequence of natural-language
prompts used to generate the FLIGHTSIM_CLAUDE application (six-process Windows
flight simulator: HOTAS transmitter, Pilot Control Station with JSBSim physics and
tactical map, UDP bus orchestrator, Synthetic Environment Manager, FlightGear OTW,
OpenStreetMap tiles) from a SysML v2 design specification, together with its
54-test regression suite and the co-evolved requirements workbook.

**Editing policy.** Prompts are reproduced from the session transcript. Tags:
- `[verbatim]` — as issued (modulo typo fixes).
- `[shortened]` — condensed for concision; content unchanged.
- `[merged]` — several consecutive turns of the same activity collapsed into one
  prompt; the activity is replicable with the single merged prompt.
- `[HIL]` — hardware-in-the-loop: the prompt reports observed runtime behavior on
  the target machine. Exact wording is machine-specific; the observed-defect text
  is retained as a representative instance. Replicators should substitute their
  own observations while keeping the report structure (numbered defects, expected
  vs. observed).
- `<...>` — placeholder for machine-specific paste (terminal output, logs,
  screenshots).

## Replication notes

1. **Prompt count.** 57 protocol entries condensing 59 raw user turns; ~40% are
   decision/feedback turns rather than generation requests — the co-evolution of
   specification and code is part of the method, not overhead.
2. **Determinism caveat.** LLM outputs are not bit-reproducible. The invariants a
   replication should reproduce: the process/port architecture fixed by the
   SysML TA; the traceability annotations [a/b/c] mandated by ground rule 4; the
   regression suite as executable acceptance criterion (grown 0 → 54+ tests);
   and the requirement-ID citations in code matching the workbook.
3. **HIL dependency.** Phases B, D, E, H depend on a physical target (HOTAS,
   FlightGear, Windows). Without hardware, the protocol truncates after Phase A/C
   plus the sandbox-verifiable parts of D, F, G; the regression suite passes
   headless (offscreen Qt) except hardware-verification legs noted in the
   workbook's V-Method column (I/D rows).
4. **Session management.** The run spanned multiple sessions with one context
   compaction; a stable project context (mounted specification files) plus
   re-upload of changed artifacts through chat proved necessary — the mounted
   mirror lagged twice, both times detected by cross-checking file content
   against the conversation (P-37/P-48 area).
